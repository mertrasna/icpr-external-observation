# Security policy

## Reporting a vulnerability

Please do not publish sensitive vulnerability details in a public issue.
Instead, contact the repository maintainer privately through the contact method
listed by the hosting platform. Include a concise description, affected path or
command, impact, and safe reproduction steps.

Do not include credentials, private keys, raw captures, real client addresses,
or unpublished server details in the report.

## Scope

Useful reports include vulnerabilities in the experiment controller, server
installation and retention tooling, infrastructure configuration, or release
process that could expose retained evidence or alter measurement integrity.

This project is a research testbed, not a public service. Do not probe the
controlled endpoint, scanner targets, or related infrastructure beyond the
authorised research procedures. Reports based on unauthorised testing may not
be reproducible safely.

## Response

The project is maintained as MSc research work, so response times are best
effort. Confirmed issues will be assessed for evidence exposure, measurement
integrity, and practical mitigation before public discussion.
